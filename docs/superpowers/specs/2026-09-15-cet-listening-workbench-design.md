## 1. 背景

使用者同时并行五条线：备考四级、读研、上班、辅导孩子功课、养生。希望有一个个人工作台协助管理。

经过需求澄清，范围收敛为**第一期只做四级这一条线**，其余四条线以后再接。

### 1.1 真实痛点（用户自选，按重要性）

1. **怕掉线** —— 某条线好几天没推进才发现
2. **记不住** —— 信息散在各处
3. **没反馈** —— 缺少进度可视化，坚持不下去

明确**未选**"抢时间/不知道此刻该干哪件"，所以本设计不做优先级调度、不做时间块规划。

### 1.2 关键约束

| 约束 | 值 | 对设计的影响 |
|---|---|---|
| 形态 | 先做 PC 端网页 | 不做手机端、不做飞书推送 |
| 录入成本 | 尽量零录入 | 数据必须由学习行为本身产出，不能靠手工填 |
| 每日时长 | 工作日 20-30 分钟碎片时间 | 必须支持随时中断、下次接上；单次任务粒度要碎 |
| 目标考试 | 2026 年 12 月四级，之后还要考六级 | 不是一次性冲刺，是长线能力建设；素材和数据结构要能复用到六级 |

## 2. 用户画像与核心判断

### 2.1 关键事实

**去年考研英语二 72 分。**

这条信息推翻了"备考四级 = 背 4500 词"的默认假设：

- 考研英语二词汇要求约 5500 词，**覆盖**四级的 4500 词
- 考研英语二阅读难度**高于**四级阅读
- 考研英语二**不考听力**

### 2.2 能力缺口分析

| 模块 | 四级占比（710 分制） | 现状判断 | 结论 |
|---|---|---|---|
| 听力 | 35%（248.5 分） | 很久没练，考研英语二无此项 | **唯一真短板**，且六级听力更难 |
| 阅读 | 35%（248.5 分） | 考研阅读难度更高 | 基本白拿 |
| 翻译 | 15%（106.5 分） | 考研有英译汉，汉译英稍陌生 | 考前套模板即可 |
| 写作 | 15%（106.5 分） | 考研大小作文练过 | 考前背模板即可 |
| 词汇 | — | 考研 5500 词 ⊃ 四级 4500 词 | 只需查漏，不需从头背 |

### 2.3 由此导出的设计原则

> **花三个月背 4500 词是无效劳动。听力才是三个月该砸的地方，而且它是唯一能同时喂给六级的投入。**

进一步的细化判断：用户的听力问题不是"不认识这个词"（词汇量足够），而是"**认识但听不出来**"——连读、弱读、语速。这个问题**只能在音频语境里治，词表卡片治不了**。

## 3. 目标与非目标

### 3.1 目标

1. 以听写驱动的精听训练为核心，**训练行为本身产出全部数据**（零录入）
2. 听错的词自动进入间隔重复队列，复习卡片带**原音频语境**
3. 一个轻量总览页，解决"怕掉线、没反馈"
4. 四级 → 六级平滑迁移：只换素材，不改系统

### 3.2 非目标（第一期明确不做）

- 手机端 / 飞书推送（用户明确"先做 PC 端"）
- 阅读、写作、翻译模块（用户不缺这些）
- 内置 4500 词表背单词（已论证为无效劳动）
- Whisper 本地转写（降级方案已够用，见 §7）
- 其余四条线：读研、上班、辅导孩子、养生（先做透一条）

但数据结构须留扩展位，见 §9.2。

## 4. 素材策略

### 4.1 调研结论

四六级真题**官方不免费公开**，网上流传的均为民间整理版，网盘链接大量失效。官方正式渠道是委员会授权出版的真题集（随书附音频下载码）。

2016 年题型改革后的真题一共只有 20 余套。**真题是稀缺品，不能当日常精听的消耗品**——三个月要练 60-90 次，真题根本不够用，且提前刷完就失去了摸底工具。

### 4.2 素材分工

| 用途 | 素材 | 来源 | 合规性 |
|---|---|---|---|
| **日常精听（约 90%）** | BBC Learning English《6 Minute English》、VOA Learning English | 官网免费 mp3 + transcript，有 RSS | 官方免费源 |
| **模考/摸底（每 2 周 1 套）** | 四级真题听力 | 正版真题书扫码 | 用户自购自备 |
| **考前冲刺（最后 3 周）** | 真题密集刷 | 同上 | 同上 |

选择 BBC 6 Minute English 作为日常主力的理由：

- 难度约 B1-B2，正好卡在四级（B1）到六级（B2）之间
- 每周更新，永远不缺素材
- 官方提供 mp3 + transcript，合规且有 RSS 可自动抓取
- 对话形式，与四级"长对话"题型接近

**系统本身不内置、不分发任何受版权保护的素材。** 真题由用户自行导入本地文件。

## 5. 核心机制：听写循环

这是整个工作台的心脏，其余模块都是它的副产品。

```
播放当前句 ──► 用户输入 ──► 提交
   ▲                          │
   │                          ▼
   └── 重听(空格)  ◄── 逐词 diff 高亮
                              │
                    ✅对  ❌错  ⬜漏
                              │
                              ▼
                  错词自动入 FSRS 队列 ──► 下一句
```

### 5.1 刻意的设计取舍

| 决策 | 理由 |
|---|---|
| **不要求全对才能推进**（词正确率 ≥80% 即可过） | 备考方法论明确警告：一句听五六遍还没听懂就该跳过，死磕是第一杀手 |
| **听满 N 遍自动亮答案**（N 默认 4，可配置） | 防止在单句上耗掉整个 20 分钟 |
| **中断即存档，下次从断点那句继续** | 20-30 分钟碎片场景的硬需求，不能要求"一次做完一篇" |
| **全键盘操作**：空格重播 / Enter 提交 / Tab 跳过 | 手不离键盘，减少操作摩擦 |
| **一篇拆 2-3 天完成** | 6 分钟音频约 60-80 句，一次 20-30 句正好 20 分钟 |
| **变速播放** 0.75x / 1.0x / 1.25x | 精听起步降速，后期提速适应考场语速 |

### 5.2 零录入是怎么成立的

听写动作本身即产出全部数据：

- 每句：听了几遍、词正确率、错了哪些词、耗时
- 每篇：整体正确率、完成进度
- 累积：高频错词、常错模式、每日时长

用户**不需要额外填写任何东西**。

### 5.3 四档强度

用户反馈"全句听写太累"，故设计四档，一键切换，系统自动推荐。

| 档位 | 用户操作 | 单句耗时 | 适用场景 |
|---|---|---|---|
| 🟢 **保命档** | 听一句 → 点「懂 / 没懂」→ 看原文 | 5-8 秒 | 极度疲劳时。**3 分钟走一轮，保证 streak 不断** |
| 🔵 **轻档**（默认） | 句子显示但挖掉 3-5 个词，只填空格 | 15-20 秒 | 日常主力 |
| 🟡 **中档** | 只写实词，虚词自动补全 | 25-35 秒 | 状态不错时 |
| 🔴 **重档** | 全句完整听写 | 40-60 秒 | 周末、考前 |

**四档都产出数据**，任何一档都不算划水：保命档产出"哪些句子没听懂"，其余产出词级正确率。

**保命档的设计意图**：永远存在一个 3 分钟就能完成的最低档，这是"坚持不下去"的直接解法——断线的成本必须低到不可能断。

### 5.4 挖空词选择规则（轻档的关键）

按优先级：

1. **优先挖用户历史错词库里出现过的词** —— 等于把 SRS 复习直接嵌进听写流程
2. 其次挖实词（名词/动词/形容词/副词）中的低频词
3. **绝不挖** the / of / a / is 这类虚词 —— 听不清也不影响理解

实现上只需一个停用词表 + 词频表，不需要引入 NLP 库。

### 5.5 档位自动调节

- 默认轻档
- 连续 3 天正确率 > 90% → 提示升档
- 正确率 < 60% → 自动降档

目的是消除"每次打开要做决定"的摩擦。

### 5.6 词级 diff 规则

- 忽略大小写、标点、多余空格
- 缩写等价：don't ≡ do not，it's ≡ it is
- 同音异形词**判错**：their / there / they're 必须区分（这正是听力考点）
- 算法：词级 LCS 对齐 + 单词内 Levenshtein 容错（拼写差 1 个字母视为"听对了但拼错"，单独标记，不计入错词库）

## 6. 错词 → 间隔重复（替代"背 4500 词"）

听写错的词自动入队，用 **FSRS** 算法调度。

### 6.1 为什么用 FSRS 而不是 SM-2

- FSRS 基于 7 亿+ 条真实复习记录训练，在相同记忆保持率下**减少 20-30% 复习量**
- SM-2 存在"低间隔地狱"（ease factor 易降难升，连按几次 Again 后间隔几乎不增长）
- FSRS 支持设定目标记忆保持率（如 90%），SM-2 无此机制

已知前提：约 1000 次复习以下，FSRS 无法拟合个人模型，会回退默认参数，表现与 SM-2 接近。这对本项目可接受——前期数据量本来就小。

实现使用 `ts-fsrs`（open-spaced-repetition 官方 TypeScript 实现）。

### 6.2 卡片形态（关键差异）

> **不是**「abandon — vt. 放弃」这种词表卡
> **而是**「该词所在的原句 + 一个播放按钮」，点一下重听当初听错的那句话

理由见 §2.3：用户的问题是"认识但听不出来"，必须在音频语境里治。

## 7. 音频切句：三级降级策略

原本考虑用 Whisper / WhisperX 做强制对齐，调研后否决：

- 本机**没有 ffmpeg**
- WhisperX 强制对齐需要 torch + wav2vec2 模型，数 GB 依赖
- CPU 上对齐阶段是瓶颈（未做批处理，逐 segment 顺序处理）

**关键认识**：听写训练只需要句子的起止时间，误差 ±0.3 秒完全可接受（前后各留 0.2s padding），**不需要词级对齐**。这个认识砍掉了整条重依赖链。

改用三级降级：

| 情况 | 处理方式 | 依赖 |
|---|---|---|
| 素材带 LRC / SRT 字幕 | 直接解析，时间戳现成 | 零 |
| 只有 mp3 + 纯文本原稿 | 浏览器 Web Audio API 做静音检测切句，与原文按句自动配对；对不齐处提供拖拽微调 UI | 零（纯前端） |
| 只有 mp3 | 本地 Whisper 转写 | 可选功能，用时再装，第一期不做 |

BBC/VOA 官方素材均带 transcript，绝大多数情况走前两级。

### 8.3 总览页

## 11. 三个月路线

| 阶段 | 工作台的事 | 用户的事 |
|---|---|---|
| 第 1-2 周 | 工作台跑起来，接上 BBC 6 Minute English | 做一套真题听力**摸底**，确定真实水平 |
| 第 3-8 周 | 每天轻档 20 分钟，错词自动累积 | 每 2 周一套真题模考，看曲线 |
| 第 9-11 周 | 升到中/重档，真题密集刷 | 背写作/翻译模板（不用工具，考前两周突击） |
| 最后 1 周 | 只做保命档保手感 | 熟悉答题卡时间分配（听力结束即收卷，须边听边涂） |

考试信息备忘：四级总时长 125 分钟；听力约 25 分钟，结束后暂停 5 分钟收答题卡 1（含作文与听力），故**必须边听边涂卡**。

## 12. 被否决的方案（记录理由，避免重复讨论）

| 方案 | 否决理由 |
|---|---|
| 内置 4500 词表，系统化背词 | 用户考研英语二 72 分，词汇量已覆盖四级。属无效劳动 |
| 纯追踪面板（倒计时 + 打卡 + 成绩曲线，学习在别处） | 不解决听力短板，且完全依赖自律，正好踩中用户"坚持不下去"的痛点 |
| 全科应试台（听说读写译全模块） | 70% 工程量花在用户不缺的能力上 |
| WhisperX 强制对齐做切句 | 本机无 ffmpeg；需数 GB 依赖；CPU 慢。而听写只需 ±0.3s 精度，不需要词级对齐 |
| 跟读 / 影子跟读替代听写 | 自动判分难度大得多，需重新设计评分机制。可作为后续扩展 |
| 五条线一起做 | 用户主动收敛为"暂时只考虑四级"。先做透一条 |

## 13. 未来扩展方向（不在第一期范围）

1. **接六级**：只需新增 `materials.source = cet6` 和更难的素材源，系统无需改动
2. **接其余四条线**：复用 `lane` 字段、热力图、掉线预警。读研/上班可尝试用文件 mtime、git 提交作为自动心跳源
3. **手机端 / 飞书推送**：用户已有 WSL 上的飞书机器人（lark-channel-bridge）和 feishu-cli，可复用为提醒通道
4. **跟读 / 影子跟读模式**
5. **Whisper 本地转写**（仅在遇到无 transcript 素材时）
