## 1. 背景

使用者同时并行五条线：备考四级、读研、上班、辅导孩子功课、养生。希望有一个个人工作台协助管理。

经过需求澄清，范围收敛为**第一期只做四级这一条线**，其余四条线以后再接。

### 1.1 真实痛点（用户自选，按重要性）

1. **怕掉线** —— 某条线好几天没推进才发现
2. **记不住** —— 信息散在各处
3. **没反馈** —— 缺少进度可视化，坚持不下去

明确**未选**"抢时间/不知道此刻该干哪件"，所以本设计不做优先级调度、不做时间块规划。

### 1.2 关键约束

| 约束 | 值 | 对设计的影响 |
|---|---|---|
| 形态 | 先做 PC 端网页 | 不做手机端、不做飞书推送 |
| 录入成本 | 尽量零录入 | 数据必须由学习行为本身产出，不能靠手工填 |
| 每日时长 | 工作日 20-30 分钟碎片时间 | 必须支持随时中断、下次接上；单次任务粒度要碎 |
| 目标考试 | 2026 年 12 月四级，之后还要考六级 | 不是一次性冲刺，是长线能力建设；素材和数据结构要能复用到六级 |

## 2. 用户画像与核心判断

### 2.1 关键事实

**去年考研英语二 72 分。**

这条信息推翻了"备考四级 = 背 4500 词"的默认假设：

- 考研英语二词汇要求约 5500 词，**覆盖**四级的 4500 词
- 考研英语二阅读难度**高于**四级阅读
- 考研英语二**不考听力**

### 2.2 能力缺口分析

| 模块 | 四级占比（710 分制） | 现状判断 | 结论 |
|---|---|---|---|
| 听力 | 35%（248.5 分） | 很久没练，考研英语二无此项 | **唯一真短板**，且六级听力更难 |
| 阅读 | 35%（248.5 分） | 考研阅读难度更高 | 基本白拿 |
| 翻译 | 15%（106.5 分） | 考研有英译汉，汉译英稍陌生 | 考前套模板即可 |
| 写作 | 15%（106.5 分） | 考研大小作文练过 | 考前背模板即可 |
| 词汇 | — | 考研 5500 词 ⊃ 四级 4500 词 | 只需查漏，不需从头背 |

### 2.3 由此导出的设计原则

> **花三个月背 4500 词是无效劳动。听力才是三个月该砸的地方，而且它是唯一能同时喂给六级的投入。**

进一步的细化判断：用户的听力问题不是"不认识这个词"（词汇量足够），而是"**认识但听不出来**"——连读、弱读、语速。这个问题**只能在音频语境里治，词表卡片治不了**。

## 3. 目标与非目标

### 3.1 目标

1. 以听写驱动的精听训练为核心，**训练行为本身产出全部数据**（零录入）
2. 听错的词自动进入间隔重复队列，复习卡片带**原音频语境**
3. 一个轻量总览页，解决"怕掉线、没反馈"
4. 四级 → 六级平滑迁移：只换素材，不改系统

### 3.2 非目标（第一期明确不做）

- 手机端 / 飞书推送（用户明确"先做 PC 端"）
- 阅读、写作、翻译模块（用户不缺这些）
- 内置 4500 词表背单词（已论证为无效劳动）
- Whisper 本地转写（降级方案已够用，见 §7）
- 其余四条线：读研、上班、辅导孩子、养生（先做透一条）

但数据结构须留扩展位，见 §9.2。

## 4. 素材策略

### 4.1 调研结论

四六级真题**官方不免费公开**，网上流传的均为民间整理版，网盘链接大量失效。官方正式渠道是委员会授权出版的真题集（随书附音频下载码）。

2016 年题型改革后的真题一共只有 20 余套。**真题是稀缺品，不能当日常精听的消耗品**——三个月要练 60-90 次，真题根本不够用，且提前刷完就失去了摸底工具。

### 4.2 素材分工

| 用途 | 素材 | 来源 | 合规性 |
|---|---|---|---|
| **日常精听（约 90%）** | BBC Learning English《6 Minute English》、VOA Learning English | 官网免费 mp3 + transcript，有 RSS | 官方免费源 |
| **模考/摸底（每 2 周 1 套）** | 四级真题听力 | 正版真题书扫码 | 用户自购自备 |
| **考前冲刺（最后 3 周）** | 真题密集刷 | 同上 | 同上 |

选择 BBC 6 Minute English 作为日常主力的理由：

- 难度约 B1-B2，正好卡在四级（B1）到六级（B2）之间
- 每周更新，永远不缺素材
- 官方提供 mp3 + transcript，合规且有 RSS 可自动抓取
- 对话形式，与四级"长对话"题型接近

**系统本身不内置、不分发任何受版权保护的素材。** 真题由用户自行导入本地文件。

## 5. 核心机制：听写循环

这是整个工作台的心脏，其余模块都是它的副产品。

```
播放当前句 ──► 用户输入 ──► 提交
   ▲                          │
   │                          ▼
   └── 重听(空格)  ◄── 逐词 diff 高亮
                              │
                    ✅对  ❌错  ⬜漏
                              │
                              ▼
                  错词自动入 FSRS 队列 ──► 下一句
```

### 5.1 刻意的设计取舍

| 决策 | 理由 |
|---|---|
| **不要求全对才能推进**：**错 ≤1 个考察词即算过** | 备考方法论明确警告：一句听五六遍还没听懂就该跳过，死磕是第一杀手。**不用百分比阈值**——轻档典型只挖 3 个空，80% 等价于必须 3/3 全对，反而比重档更严苛，与本条标题自相矛盾 |
| **没过也放行**，只标记该句 `weak`，不强制重听 | 强制重听 = 死磕，与上一条冲突。`weak` 句在该篇结束时汇总，供用户选择性回看 |
| **听满 N 遍自动亮答案**（N 默认 4，可配置） | 防止在单句上耗掉整个 20 分钟 |
| **自动亮答案后不再提交**，该句记 `revealed` | 已看过答案再打字没有测量意义。`accuracy` 记 0，正常计入分母 |
| `revealed` 句**只有该档位实际考察的词**入错词库 | **不是"句中所有关键词"**。轻档只挖 3-5 个空，其余实词是明明白白显示在屏幕上的，用户从未被要求产出。若全部入库，一篇 60-80 句的素材只要 10% 触发揭示就会涌入几十个从没考过的词，冲垮 20-30 分钟的时间预算，并污染 §8.3 的高频错词 TOP 10 |
| `revealed` 句的考察词中命中的 **due 词按 `Again` 写入 `reviews`** 并更新调度，当日移出独立复习队列 | 见 §6.4。若不写，这类句子里的 due 词只进错词库不更新调度，当天仍会被独立复习模块再考一遍——**双重调度恰恰在最该记一次 `Again` 的句子上保留下来** |
| **`skipped`（Tab 跳过）的行为定死**：`tested_words_total = 0`、`accuracy = NULL`、**不入错词库、不触发 SRS 联动**、但**计入 `sentences_done`** | 与保命档同构。这几个选择的后果是相反的：若记 0 分，频繁跳过会把用户自动降档；若记 `NULL`，跳过完全免费。选后者——跳过是碎片时间下的正常行为，不该被惩罚 |
| **中断即存档，下次从断点那句继续** | 20-30 分钟碎片场景的硬需求，不能要求"一次做完一篇" |
| **全键盘操作**：空格重播 / Enter 提交 / Tab 跳过 | 手不离键盘，减少操作摩擦 |
| **一篇拆 2-3 天完成** | 6 分钟音频约 60-80 句，一次 20-30 句正好 20 分钟 |
| **变速播放** 0.75x / 1.0x / 1.25x | 精听起步降速，后期提速适应考场语速 |

### 5.2 零录入是怎么成立的

听写动作本身即产出全部数据：

- 每句：听了几遍、词正确率、错了哪些词、耗时
- 每篇：整体正确率、完成进度
- 累积：高频错词、常错模式、每日时长

用户**不需要额外填写任何东西**。

### 5.3 四档强度

用户反馈"全句听写太累"，故设计四档，一键切换，系统自动推荐。

| 档位 | 用户操作 | 单句耗时 | 适用场景 | 产出的 accuracy |
|---|---|---|---|---|
| 🟢 **保命档** | 听一句 → 点「懂 / 没懂」→ 看原文 | 5-8 秒 | 极度疲劳时。**3 分钟走一轮，保证 streak 不断** | **无**（`accuracy = NULL`） |
| 🔵 **轻档**（默认） | 句子显示但挖掉 3-5 个词，只填空格 | 15-20 秒 | 日常主力 | 考察词命中率 |
| 🟡 **中档** | 只写考察词，**非考察词**自动补全 | 25-35 秒 | 状态不错时 | 考察词命中率 |
| 🔴 **重档** | 全句完整听写 | 40-60 秒 | 周末、考前 | 考察词命中率（**非考察词写错不扣分**） |

**四档都产出数据**，任何一档都不算划水：保命档产出"哪些句子没听懂"，其余产出考察词命中率。

⚠️ 中档的"自动补全"与重档的"不扣分"只作用于**非考察词**。考察词里的功能词（如 `their` / `its` / `than`）**照常要写、照常扣分** —— 原因见 §5.3.1 的高危同音组。

**保命档的设计意图**：永远存在一个 3 分钟就能完成的最低档，这是"坚持不下去"的直接解法——断线的成本必须低到不可能断。

### 5.3.1 关键词与统一口径（重要）

四档考察的词数不同，若各自用"答对词数 / 本档考察词数"作为正确率，**分母不可比**：保命档接近 100%、轻档只判 3-5 个词、重档判全句。三处机制（§5.1 的 80% 阈值、§5.5 的升降档、§8.3 的趋势曲线）如果共用这个数，会出现"疲劳时切保命档 → 曲线不降反升 → 自动升回重档"的震荡，与保命档的设计意图正面冲突。

因此区分两个概念——**这两个词在本文档中严格区分，不可混用**：

| 概念 | 归属 | 定义 |
|---|---|---|
| **关键词**（key words） | **句子**的静态属性，导入时预计算 | 该句所有**实词**（§5.4）∪ 该句中属于**高危同音组**的词 |
| **考察词**（tested words） | **本次作答**的属性，运行时确定 | 本次实际要求用户产出的词。由档位 + 该句中的用户历史错词共同决定 |

#### 高危同音组（必须有，否则核心能力失效）

这是一个**必须单列的例外**：`their` / `there` / `they're`、`its` / `it's`、`than` / `then`、`to` / `too`、`your` / `you're`、`were` / `where` / `we're`、`of` / `off`、`whose` / `who's`、`weather` / `whether` —— 这些词**全部是停用词**，按 §5.4 的"实词 = 不在停用词表中的词"会被划为虚词。

若不做例外处理，它们会被中档自动补全、被重档免于扣分、且永远不进轻档的挖空候选。**结果是 §5.6 花整节论证要抓的同音异形词能力，在默认档位上结构性失效** —— 系统对最典型的连读弱读错误完全失明。

因此：**高危同音组中的词一律计入关键词，无论它是不是停用词。**

该表约 20-30 组，随仓库版本控制。它不同于 §5.6 明确拒绝的"易混词黑名单"：那里要穷举所有可能听错的词对（永远列不全），这里只需覆盖**高频功能词**的同音组——英语里这类组是封闭且稳定的，可以列全。

#### 候选词池与各档的考察范围

```
候选词池 = 该句关键词 ∪ 该句中出现的用户历史错词
```

| 档位 | 考察词 | accuracy |
|---|---|---|
| 保命档 | 空集 | `NULL` |
| 轻档 | 从候选池按 §5.4 优先级取 N 个（挖空） | 填对数 / N |
| 中档 | 候选池**全部** | 写对数 / 候选池大小 |
| 重档 | 候选池全部（用户写全句，但只统计考察词） | 同上 |

`attempts` 存 `tested_words_total`、`tested_words_correct` 两个原始计数与 `tested_words_json`（本次实际考察的词集合，**所有档位都落**），`accuracy` 为二者之商。存原始计数与考察词集合而非只存商，是为了后续能按任意口径重算。

**全局规则：`tested_words_total = 0` 时 `accuracy = NULL`**（保命档、以及候选池为空的极短句），不得写 0 或 100。

**跨档比较规则**（三处机制统一遵守）：

1. **保命档不参与任何正确率统计**，只计入 streak 与"没听懂的句子"清单
2. **趋势曲线按档位分线绘制**，不同档位的点不连成一条线，切换档位处断开并标注档位标签
3. **升降档判定只在同档位内累计**（见 §5.5）
4. 真正跨档可比的硬指标是**模考听力分数**（§8.4），趋势页以它为主指标、听写正确率为辅

轻档虽然只考察候选池的子集，但由于挖空优先命中历史错词和低频实词（§5.4），其命中率在同档位内纵向可比——这已经满足升降档与趋势观察的需要。

### 5.4 挖空词选择规则（轻档的关键）

#### 实词的可执行定义

本项目**不引入 POS 标注库**，因此"实词"采用一个近似但无歧义的定义：

> **实词 = 不在停用词表中的词**

停用词表使用固定的英文 stopwords 列表（冠词、介词、连词、助动词、系动词、代词、常用副词等，119 词），随项目版本控制，不动态生成。

⚠️ **这个定义只用于"挖空优先级"和"关键词预计算"，绝不用于决定中档的自动补全范围。** 中档补全的依据是**考察词 / 非考察词**，不是实词 / 虚词——用停用词表决定补全范围会让 `their` / `its` / `than` 全被自动填上，§5.3.1 堵住的失效通道就原样回来了。

这个近似会把少量虚词误判为实词（反之亦然），但对训练效果无实质影响——听写训练关心的是"能不能听出承载信息的词"，边界上的几个词判错无所谓。

#### 挖空词的选择（轻档）

从**候选词池**（§5.3.1）按优先级排序后取前 N 个：

1. **该句中已到期（`due <= today`）的历史错词** —— 这是把 SRS 复习嵌进听写流程的具体机制，详见 §6.4
2. **该句中高危同音组的词**（§5.3.1）—— 刻意排在普通实词之前，这正是本项目要抓的核心错误类型
3. 该句中未到期的历史错词
4. 低频实词：**词频 rank > 3000** 的实词，rank 越大优先级越高
5. 其余实词

**N 的取值**：`N = min(5, max(1, round(候选池大小 × 0.4)))`

注意实际取值范围是 **1-5 而非 3-5**：池 ≤2 时 N=1，池 3-6 时 N=2。与 §5.1 的"错 ≤1 个即算过"叠加后，**N ≤ 2 的句子必然判 `ok`**，`weak` 永远不会在短句上触发。因此"错 ≤1 即算过"附加一个前置条件：**仅当 N ≥ 3 时适用；N ≤ 2 时要求全对才算 `ok`**。

- 候选池不足时有几个挖几个
- 候选池**为空**（极短句如 "Yes, of course."）→ 该句以保命档形式呈现（听 + 看原文），`accuracy = NULL`

**词频表**：使用开源英文词频 rank 列表（COCA 或 Google Books 频次表的前 2 万词，约数百 KB），随项目版本控制。该依赖已列入 §10。

### 5.5 档位自动调节

- 默认轻档
- 判定**只在同档位内累计**：连续 3 个「该档位有记录的日子」正确率 > 90% → 提示升档；< 60% → 自动降档
- **保命档完全不参与判定**：保命档的日子既不计入"连续 3 天"的计数，也不中断已累计的计数（视为跳过）
- **自动降档的下限是轻档。保命档只能手动进入。**
- 升档是**提示**（用户确认后才生效），降档是**自动**的 —— 不对称是刻意的：升档增加负担必须用户同意，降档减少负担应当立即生效

降档下限这条不能省：档位梯子是 保命/轻/中/重，若允许从轻档自动降到保命档，用户就再也升不回来了——保命档产不出正确率，永远凑不满"连续 3 天 > 90%"的升档条件。保命档的定位是**疲劳时的手动逃生舱**，不是自动下坠的终点。

目的是消除"每次打开要做决定"的摩擦，同时保证疲劳期切保命档不会被系统"惩罚性"地推回重档。

### 5.6 词级 diff 规则

这一节必须写死，因为规则之间极易互相矛盾——同音异形词既是"最该判错的东西"，又恰好落在"拼写容错"的射程内。

#### 归一化流水线（顺序固定，不可调换）

对原文和用户输入各跑一遍，**严格按此顺序**：

1. 转小写
2. **展开缩写**，仅限固定白名单：`don't→do not`、`doesn't→does not`、`didn't→did not`、`can't/cannot→can not`、`won't→will not`、`isn't→is not`、`aren't→are not`、`wasn't→was not`、`weren't→were not`、`gonna→going to`、`wanna→want to`
3. 去除**词首尾**标点（词内撇号保留）
4. 折叠连续空白
5. 按空白分词

**`'s` / `'re` / `'ve` / `'ll` 一律不展开。** 理由：`it's` 与 `its`、`they're` 与 `their` 在听感上有真实差别，正是四六级听力的考点；展开会让它们塌缩成同一串，等于放过了最该抓的错误。归一化后 `it's` 与 `its` 是两个不同 token，天然判错——这是期望行为。

白名单里的 `n't` 类缩写则相反：`don't` 与 `do not` 在连读中确实难以区分，且 transcript 的写法本身就不稳定，判错属于误伤。

#### 拼写容错规则（取代原先的"编辑距离 1 一律容错"）

原规则有致命缺陷：`there`↔`their` 编辑距离为 1，`than`↔`then`、`week`↔`weak`、`affect`↔`effect` 亦然。按原规则这些会被判成"拼写失误"并排除出错词库——而它们恰恰是本系统存在的理由。

**修正后的规则**：

> 用户输入的词与原文词编辑距离 ≤1 时，看**用户打出的那个串本身是不是一个合法英文单词**：
> - **是合法单词** → 判**错**（用户听成了另一个词），正常计入错词库
> - **不是任何英文单词** → 判为**拼写失误**（`spelling_slip`），计入 accuracy 分子，但**不**进错词库

例：

| 原文 | 用户输入 | 判定 | 理由 |
|---|---|---|---|
| their | there | ❌ 错 | `there` 是合法词 → 听错了 |
| then | than | ❌ 错 | `than` 是合法词 → 听错了 |
| receive | recieve | ⚠️ 拼写失误 | `recieve` 不是英文词 → 听对了，手滑 |
| government | goverment | ⚠️ 拼写失误 | 同上 |

这条规则不需要维护易混词黑名单（黑名单永远列不全），只需要一份**合法英文词表**。该依赖已列入 §10。

#### 计分规则

| 情形 | 计入 accuracy 分子 | 计入分母 | 进错词库 |
|---|---|---|---|
| 完全正确 | ✅ | ✅ | ❌ |
| 拼写失误（`spelling_slip`） | ✅ | ✅ | ❌ |
| 听成别的词 | ❌ | ✅ | ✅ |
| 漏写（`⬜`） | ❌ | ✅ | ✅ |
| 多写（原文没有的词） | — | ❌ | ❌ |

只有**考察词**（§5.3.1）参与计分；非考察词的错漏不影响 accuracy。

#### 对齐算法

词级 LCS 对齐确定对应关系，再逐对应词套用上述容错与计分规则。

#### 分词细则（BBC 新闻类素材里这几类不罕见）

| 情况 | 规则 |
|---|---|
| 连字符词 | `well-known` 与 `well known` 视为等价：分词前把词内连字符替换为空格 |
| 数字与量词 | transcript 的 `£5m`、`2019` 与用户打的 `five million`、`twenty nineteen` **判为等价**：归一化时把数字统一转为英文读法后再比较。若实现成本过高，则**将含数字的词排除出考察词**——绝不能让它当错词入库，那是格式差异不是听力问题 |
| 专有名词大小写 | 已在第 1 步统一小写，不单独处理 |

#### 一个实现级的坑

归一化第 2 步"展开缩写"**必须在字符串级做正则替换**，不能等分词后再逐 token 查白名单。

原因：分词前 `don't,`（带尾随逗号）是一个 token，与白名单键 `don't` 不相等，逐 token 查表会完全匹配不上，等于白名单失效。而第 3 步去标点又发生在展开之后——顺序不能调换（调换会导致 `it's` → `its`，见上文）。

正确做法：第 2 步用带词边界的正则在整句字符串上替换。

## 6. 错词 → 间隔重复（替代"背 4500 词"）

听写错的词自动入队，用 **FSRS** 算法调度。

### 6.1 为什么用 FSRS 而不是 SM-2

- FSRS 基于 7 亿+ 条真实复习记录训练，在相同记忆保持率下**减少 20-30% 复习量**
- SM-2 存在"低间隔地狱"（ease factor 易降难升，连按几次 Again 后间隔几乎不增长）
- FSRS 支持设定目标记忆保持率（如 90%），SM-2 无此机制

已知前提：约 1000 次复习以下，FSRS 无法拟合个人模型，会回退默认参数，表现与 SM-2 接近。这对本项目可接受——前期数据量本来就小。

实现使用 `ts-fsrs`（open-spaced-repetition 官方 TypeScript 实现）。

### 6.2 卡片形态（关键差异）

> **不是**「abandon — vt. 放弃」这种词表卡
> **而是**「该词所在的原句 + 一个播放按钮」，点一下重听当初听错的那句话

理由见 §2.3：用户的问题是"认识但听不出来"，必须在音频语境里治。

播放的是**最近一次听错该词的那一句**（`words.last_error_sentence_id`），不是第一次。理由：最近的错误语境更能反映当前的薄弱点。

### 6.3 评分（rating）从哪来 —— 复习也是听写，不手点按钮

FSRS 需要每次复习给出 `Again / Hard / Good / Easy` 四档评分。常规做法是让用户自己点四个按钮，但这与 §3.1 的**零录入**原则冲突（且用户自评不可靠）。

因此复习环节**复用听写形式，自动判分**：

1. 播放该词所在的原句，**不显示文字**
2. 用户只需打出**那一个词**（不是整句）
3. 按行为自动映射评分：

| 用户行为 | rating |
|---|---|
| 选择"不听了，我记得"直接打对 | `Easy` |
| 播放 1 遍即打对 | `Good` |
| 重听 2-3 遍后打对 | `Hard` |
| 重听 ≥4 遍，或打错 | `Again` |

拼写失误（§5.6 判定为 `spelling_slip`）视为打对，按重听次数落到对应档。

这样复习既保持零录入，形式又与核心机制一致——都是"在音频语境里把这个词听出来"。

### 6.4 听写流程中的 SRS 联动

**触发条件是"任一档位实际考察到了 due 词"，不限于轻档挖空。**

这一点必须写准：中档和重档的考察词是候选池全集，其中同样包含已到期的历史错词。若只在轻档联动，中/重档考察过的 due 词当天仍会留在独立复习队列里被再考一遍——这正是要消除的双重调度。§11 路线图第 9-11 周主用中/重档，这不是边角场景。

具体规则：

- 任一档位（保命档除外，它不考察词）的考察词命中 due 词，用户作答后**按 §6.3 同一套映射写入 `reviews`**，并更新该词的 FSRS 调度
- 该词当日**不再出现在独立复习模块的队列中**
- 独立复习模块只处理**当日未被听写流程覆盖到的 due 词**
- 保命档不考察词，**不触发任何联动**

**`revealed` 句同样触发联动**：听满 4 遍被自动揭示的句子，其考察词中命中的 due 词按 **`Again`** 写入 `reviews` 并更新调度，当日移出独立复习队列。虽然 §5.1 规定揭示后不再提交，但"听了 4 遍还听不出来"本身就是一个明确的 `Again` 信号，不该丢。

**rating 的取值口径**：听写路径下 `replay_count` 是**整句级**的，不是单词级。一句里有两个 due 词、整句重听 3 遍，两个词都拿 `Hard`。这是可接受的近似——单词级重听次数在听写场景下无法测量。

§6.3 表中"重听 ≥4 遍 → `Again`"这一档在听写路径**不可达**（第 4 遍就触发自动揭示了），听写路径的 `Again` 全部来自"打错"和上述 `revealed` 两条通道。

`Easy` 在听写路径同样**不可达**（听写没有"不听了，我记得"这个入口），只有独立复习模块能产生 `Easy`。

**轻档的 due 词泄漏**：轻档只挖 N 个空，句中其余 due 错词是**明文显示**的。若当天晚些时候独立复习模块再播这句让用户拼写，用户几分钟前刚在屏幕上看过，评分会虚高（本该 `Again` 的拿到 `Good`）。轻档是默认档，这不是边角场景。

处理：轻档提交时，把"本句中可见但未被挖空的 due 词"标记为**当日已曝光**，推迟一天再排。

实现要求：听写提交与复习提交走**同一个 rating 计算函数**和**同一个 FSRS 调度入口**，不允许两套逻辑。

### 6.5 毕业条件

满足全部条件的词标记为 `graduated`，移出复习队列（记录保留，仍计入统计）：

- FSRS `state = Review`
- 最近连续 3 次评分为 `Good` 或 `Easy`
- `stability > 60` 天

毕业后若在后续听写中再次听错，`state` 重置并重新入队，`error_count` 累加。

## 7. 音频切句：三级降级策略

原本考虑用 Whisper / WhisperX 做强制对齐，调研后否决：

- 本机**没有 ffmpeg**
- WhisperX 强制对齐需要 torch + wav2vec2 模型，数 GB 依赖
- CPU 上对齐阶段是瓶颈（未做批处理，逐 segment 顺序处理）

**关键认识**：听写训练只需要句子的起止时间，误差 ±0.3 秒完全可接受（前后各留 0.2s padding），**不需要词级对齐**。这个认识砍掉了整条重依赖链。

改用三级降级：

| 情况 | 处理方式 | 依赖 |
|---|---|---|
| 素材带 LRC / SRT 字幕 | 直接解析，时间戳现成 | 零 |
| 只有 mp3 + 纯文本原稿 | 浏览器 Web Audio API 做静音检测切句，与原文按句自动配对；对不齐处提供拖拽微调 UI | 零（纯前端） |
| 只有 mp3 | 本地 Whisper 转写 | 可选功能，用时再装，第一期不做 |

BBC/VOA 官方素材均带 transcript，绝大多数情况走前两级。

### 7.1 实施分期（第二级是独立子系统，不要一次做完）

静音检测切句在文档里只占一行，实际是个独立子系统：分段能量阈值、最短静音时长、段数与原文句数不匹配时的兜底策略、拖拽微调 UI——每一项都要单独设计。**它不该阻塞核心听写循环的落地。**

因此：

| 阶段 | 切句能力 | 说明 |
|---|---|---|
| **第一阶段** | 仅支持带 LRC / SRT 的素材 + 手工切句 | 核心听写循环先跑通。时间戳现成，零算法风险 |
| **第二阶段** | 加静音检测自动切句 + 拖拽微调 | 单列一个实施阶段，有独立的验收标准 |
| 后续 | Whisper 转写 | 仅在遇到无 transcript 素材时才做 |

第一阶段就能开始每天训练——这比"等一个完美的自动切句"重要得多。

### 8.1 精听工作台（核心）

见 §5。

### 8.2 生词复习

见 §6。

### 8.3 总览页

打开即是一个大按钮 **「继续听写」**，直接跳回上次断点那句——零决策，降低启动摩擦。

下方内容：

- **倒计时**：距 2026 年 12 月四级考试剩余天数
- **打卡热力图**（GitHub 贡献图样式）+ 连续天数。**保命档同样点亮热力图** —— 它存在的意义就是保住这条链
- **模考听力分数曲线** —— **主指标**，唯一跨档可比的硬证据（见 §8.4）
- **听写正确率趋势曲线** —— 辅指标，**按档位分线绘制**（见 §5.3.1），保命档的日子不产生数据点
- **掉线预警**：超过 3 天未练，卡片变红
- **高频错词 TOP 10**（按 `words.error_count` 排序）

为什么主辅要分清：听写正确率会随档位切换跳变，且轻档的分母是自选的挖空词，不适合当"我变强了"的证据。模考分数才是。

### 8.4 模考记录

全系统**唯一需要手工录入**的地方：每两周做一套真题，填四个模块得分。一次约 30 秒，可接受。

#### 分数口径（必须写死，否则实现者只能自己编）

四六级官方采用**常模参照的标准分转换**，非线性、且每次考试的常模不同，**无法在本地精确复现**。因此：

- 录入字段分两组：
  - `*_raw`：答对题数（可选填，来自真题册的自测）
  - `*_score`：710 分制分值 —— **由用户从真题书附带的换算表读取后填入**；若真题书无换算表，系统按"答对率 × 该模块满分"线性估算并**回填到该字段**
  - 各模块满分：听力 248.5、阅读 248.5、写作 106.5、翻译 106.5
- 线性兜底估算需要答对率的分母，因此表中存 `*_raw_total`（四级听力 25 题、阅读 30 题）。**存成字段而非硬编码常量**——六级题量不同，接六级时要用
- `mocks.total` **由四项 `*_score` 相加得出，系统计算，不接受录入**
- 写作与翻译无客观答案，只填 `*_score`（用户按范文自评档位，8 分档 ≈ 及格线）

**UI 必须明示**：此分数是粗略估算，**误差可能很大**，仅用于看自己的纵向趋势，不能当作对真实考试成绩的预测。

误差来源有两层：一是 CET 采用常模参照的标准分转换，非线性且每次考试常模不同；二是各 Section 每题权重并不相等，"答对率 × 满分"的线性估算本身就与真实折算差得不少。把一个不可能精确的数字包装成精确的，比不给更糟。

### 8.5 素材管理

按实施优先级排列：

1. **本地文件导入**（音频 + 原文 / LRC / SRT）—— 第一阶段必须有，否则系统跑不起来
2. **切句结果的人工微调 UI**
3. **RSS 自动抓取** BBC Learning English / VOA Learning English（需后端，浏览器跨域抓不了）

RSS 抓取虽然是"零录入"理念的体现，但相对核心闭环优先级最低：手动下一个 mp3 + 复制一段 transcript 只要两分钟，而核心听写循环不通，整个系统就没有意义。**先让训练能跑起来，再谈自动化供料。**

## 9. 数据模型

### 9.1 表结构

```
materials   素材      id, title, source, lane, audio_path, transcript_path,
                      duration_ms, sentence_count, current_sentence_idx,
                      added_at, finished_at

sentences   句子      id, material_id, idx, start_ms, end_ms, text,
                      key_words_json          -- 仅静态部分：实词 ∪ 高危同音组词
                                              -- 导入时预计算。历史错词不在此列

attempts    听写记录  id, sentence_id, mode, input,
                      tested_words_total, tested_words_correct, accuracy,
                      tested_words_json,      -- 本次实际考察的词集合，所有档位都落
                                              -- 中/重档的候选池含历史错词，事后不可复现
                      outcome,                -- ok | weak | revealed | skipped
                      comprehended,           -- 仅保命档：懂/没懂，其余档为 NULL
                      replay_count, duration_ms, created_at

words       生词      word (PK), first_seen_sentence_id, last_error_sentence_id,
                      error_count, graduated,
                      -- 以下为 ts-fsrs Card 的完整字段，缺一不可
                      due, stability, difficulty, elapsed_days,
                      scheduled_days, reps, lapses, state, last_review

reviews     复习记录  id, word, rating, source,   -- source: review | dictation
                      replay_count, reviewed_at

mocks       模考      id, date, source,       -- cet4 | cet6
                      listening_raw, listening_raw_total, listening_score,
                      reading_raw,   reading_raw_total,   reading_score,
                      writing_score, translation_score,
                      total,                  -- 计算得出，不录入
                      note

daily       日汇总    date, lane, minutes, sentences_done,
                      mode_distribution_json, -- 各档位句数分布，非单值
                      accuracy_by_mode_json,  -- 各档位正确率，不混算
                      streak_kept
```

几处刻意的设计：

- `attempts.accuracy` 可为 `NULL`（保命档、或 `tested_words_total = 0` 的极短句），消费方必须处理空值，**不得当 0 或 100**
- **`sentences.key_words_json` 只固化静态部分**（实词 ∪ 高危同音组词）。历史错词是随时间增长的，导入时算不出来，必须在运行时取并集得到候选词池。若把历史错词也写进这个字段，要么永远漏掉（§5.4 的优先级 1/3 失去依据），要么每天重算全表
- **`tested_words_*` 而不是 `key_words_*`**：关键词是句子的静态属性，考察词是本次作答的属性，两者在轻档下不相等。用同一个名字会让"只有关键词参与计分"这句话产生歧义
- `tested_words_total` / `tested_words_correct` 存原始计数、`tested_words_json` 存实际考察词集合 —— 三者齐备才能按任意口径重算；只存商或只存计数都算不回去。**所有档位都要落 `tested_words_json`，不只轻档**：中/重档的考察词 = 候选池全集，而候选池含随时间增长的历史错词，**事后不可复现**
- 三个不同含义的 `source` 字段（`materials.source` = bbc/voa/cet4/cet6、`mocks.source` = cet4/cet6、`reviews.source` = review/dictation）在 repository 层用不同类型区分，避免串用
- **保命档同样落 `attempts` 行**（`accuracy = NULL`，`comprehended` 有值）。这一点定死，不留"可配置"的余地
- `materials.current_sentence_idx` 显式记录断点，**任何档位推进都更新它**。断点必须显式，不依赖对 `attempts` 的任何反推
- `words` 表铺平 ts-fsrs 的 Card 全部字段。`lapses`、`scheduled_days` 无法从 `reviews` 反推，必须持久化
- `reviews.source` 区分该次评分来自独立复习还是听写流程联动（§6.4），便于排查调度异常
- `daily` 的档位数据存 JSON 分布而非单值 —— 用户一天内完全可能切档

### 9.2 扩展位（为其余四条线预留）

- `materials.source`：`bbc` / `voa` / `cet4` / `cet6` —— 接六级只需新增取值
- `materials.lane` 与 `daily.lane`：`english` / `grad` / `work` / `kid` / `health` —— 第一期恒为 `english`，未来接入其余四条线时，总览页的热力图和掉线预警可直接复用

## 10. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Node 20 + Fastify，本地 `:5174` | 本机已有 Node v20.19.5；需要后端抓 RSS（浏览器跨域受限） |
| 数据 | SQLite（`better-sqlite3`） | 复习调度需频繁查询。Node 20 + Windows 通常有 prebuilt 二进制 |
| 前端 | Vite + Vue 3 | 用户熟悉（现有 crm-frontend / boss-frontend 技术栈） |
| SRS | `ts-fsrs`（**版本钉死，不用 `^`**） | FSRS 官方 TypeScript 实现。`Card` 结构在版本间变更过（新版本加过字段），而 `words` 表是按 `Card` 铺平的——浮动版本会让表结构与库悄悄错位。落库前对齐一次实际 `Card` 定义 |
| 音频 | 原生 Audio API + Web Audio API | 播放、变速、静音检测切句，零额外依赖 |
| 图表 | ECharts | 热力图、趋势图现成 |

### 10.1 静态词表依赖（随仓库版本控制，不动态下载）

| 词表 | 用途 | 规模 | 出处 |
|---|---|---|---|
| 英文停用词表 | 判定"实词"（§5.4） | 119 词 | 标准 English stopwords |
| 英文词频 rank 表 | 判定"低频词"，阈值 rank > 3000（§5.4） | 前 2 万词，数百 KB | COCA / Google Books 频次表 |
| **合法英文单词表** | 拼写容错判定（§5.6）——决定"打出来的串是不是一个真词" | 约 10 万词，数 MB | SCOWL / `words` 词表 |

第三份是 §5.6 修正规则的前提，**没有它整条容错规则无法实现**，不是可选项。

### 10.2 数据访问抽象

所有数据库操作走一层 repository 接口，不在业务代码里直接写 SQL。

理由：`better-sqlite3` 在 Windows 上存在（低概率的）编译失败风险，届时需要降级为 JSON 文件存储。有抽象层时这是换一个实现类的事，没有则要改遍全项目。这一层很薄，成本远低于它规避的风险。

本机已确认：Node v20.19.5、Python 3.12.10、git 2.47.0、C 盘剩余 551G。**无 ffmpeg**（见 §7，已规避）。

### 10.3 实施里程碑（切两刀，不要一次做完）

本 spec 覆盖的面仍然偏大：听写引擎 + SRS + 总览页 + 模考 + 素材导入 + 后端 + 三份词表。距考试只剩三个月，**能早一天开始训练，比功能完整重要得多**。

| 里程碑 | 内容 | 完成后的状态 |
|---|---|---|
| **M1** | 本地导入（LRC/SRT）+ 四档听写循环 + diff 判定 + 错词入库 + FSRS 调度 + 独立复习 | **已经可以每天训练了** |
| **M2** | 总览页 + 模考记录 + 静音检测自动切句 + RSS 自动抓取 | 反馈与自动化供料就位 |

**`daily` 表归属须在计划里写明**：§5.5 的档位自动调节要读"该档位有记录的日子的正确率"，数据源是 `daily.accuracy_by_mode_json`。但 `daily` 看起来像总览页（M2）的东西——**M1 若不做 `daily` 汇总，档位自动调节就跑不起来**。二选一：把 `daily` 划进 M1，或写明 M1 阶段从 `attempts` 现算。

M1 是完整闭环，不是半成品：素材进得来、能听写、错词能复习。M2 全部是"让这件事更舒服"的东西——重要，但不能挡在开始训练前面。

总览页被放进 M2 是刻意的：它解决的"怕掉线、没反馈"要**先有数据才有意义**，M1 跑两周后再做，那时才知道哪些指标真正有用。

## 11. 三个月路线

| 阶段 | 工作台的事 | 用户的事 |
|---|---|---|
| 第 1-2 周 | 工作台跑起来，接上 BBC 6 Minute English | 做一套真题听力**摸底**，确定真实水平 |
| 第 3-8 周 | 每天轻档 20 分钟，错词自动累积 | 每 2 周一套真题模考，看曲线 |

考试信息备忘：四级总时长 125 分钟；听力约 25 分钟，结束后暂停 5 分钟收答题卡 1（含作文与听力），故**必须边听边涂卡**。

## 12. 被否决的方案（记录理由，避免重复讨论）

| 方案 | 否决理由 |
|---|---|
| 内置 4500 词表，系统化背词 | 用户考研英语二 72 分，词汇量已覆盖四级。属无效劳动 |
| 纯追踪面板（倒计时 + 打卡 + 成绩曲线，学习在别处） | 不解决听力短板，且完全依赖自律，正好踩中用户"坚持不下去"的痛点 |
| 全科应试台（听说读写译全模块） | 70% 工程量花在用户不缺的能力上 |
| WhisperX 强制对齐做切句 | 本机无 ffmpeg；需数 GB 依赖；CPU 慢。而听写只需 ±0.3s 精度，不需要词级对齐 |
| 跟读 / 影子跟读替代听写 | 自动判分难度大得多，需重新设计评分机制。可作为后续扩展 |
| 五条线一起做 | 用户主动收敛为"暂时只考虑四级"。先做透一条 |
