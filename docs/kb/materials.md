# 素材策略与切句

## 版权红线（先读这条）

> **本仓库不包含、不分发任何听力素材。**

`.gitignore` 已排除 `materials/`、`*.mp3`、`*.wav`、`*.m4a`、`*.lrc`、`*.srt`。仓库是公开的，**任何时候都不要把音频或真题文本提交进去**。

真题由使用者自行从正版渠道获取，放在本地 `materials/` 下。

## 素材分工（不要搞混）

| 用途 | 素材 | 来源 |
|---|---|---|
| **日常精听（约 90%）** | BBC Learning English《6 Minute English》、VOA Learning English | 官网免费 mp3 + transcript，有 RSS |
| **模考/摸底（每 2 周 1 套）** | 四级真题听力 | 正版真题书扫码 |
| **考前冲刺（最后 3 周）** | 真题密集刷 | 同上 |

### 为什么真题不能当日常素材

四六级真题**官方不免费公开**，2016 年题型改革后总共只有 20 余套。三个月要练 60-90 次，**真题根本不够用**，而且提前刷完就失去了摸底工具。

真题是稀缺品，留给模考。

### 为什么选 BBC 6 Minute English 当主力

- 难度 B1-B2，正好卡在四级（B1）到六级（B2）之间
- **每周更新**，永远不缺素材
- 官方提供 mp3 + transcript，合规且有 RSS
- 对话形式，与四级"长对话"题型接近

## 切句：三级降级

听写训练只需要**句子起止时间**，误差 ±0.3 秒完全可接受（前后各留 0.2s padding）。

**不需要词级对齐。** 这个认识是砍掉整条重依赖链的关键——原本考虑的 WhisperX 强制对齐需要 torch + wav2vec2 数 GB 依赖，本机还没有 ffmpeg，而它提供的毫秒级精度我们根本用不上。

| 情况 | 处理 | 依赖 |
|---|---|---|
| 带 LRC / SRT | 直接解析，时间戳现成 | 零 |
| mp3 + 纯文本 | Web Audio API 静音检测切句 + 与原文按句配对 + 拖拽微调 | 零（纯前端） |
| 只有 mp3 | Whisper 转写 | 用时再装，第一期不做 |

BBC/VOA 官方素材都带 transcript，绝大多数走前两级。

### LRC/SRT 解析的两条实现约束（`src/shared/transcript.ts`）

- **0.2s 播放留白只在播放器加，不写进 `sentences.start_ms`/`end_ms`**。数据库存解析出来的原始时间戳。两处都加会叠成 0.4s，相邻句子的播放区间会互相重叠
- **SRT 空文本块过滤之后才重新编 `idx`**。若在过滤前就按原始块顺序编号，被丢弃的空块会在编号里留洞，`sentences.idx` 不连续——断点续做（靠 `current_sentence_idx` 定位下一句）会跳句
- LRC 只有起始时间戳，末句没有下一行可借，`endMs` 只能是 `null`，导入时用音频总时长回填（时长拿不到则退化为 `startMs + 5000`）。下游代码必须处理 `null`，不能假设它总是数字
- LRC 行序不保证按时间排列，解析时先按 `startMs` 排序再推导 `endMs`（否则乱序文件会算出负数或重叠区间）

## 实施分期（重要）

静音检测切句在设计文档里只占一行，**实际是个独立子系统**：分段能量阈值、最短静音时长、段数与句数不匹配时的兜底、拖拽微调 UI，每项都要单独设计。

**它不该阻塞核心听写循环的落地。**

| 阶段 | 切句能力 |
|---|---|
| **第一阶段** | 仅支持带 LRC/SRT 的素材 + 手工切句。核心循环先跑通，零算法风险 |
| **第二阶段** | 静音检测自动切句 + 拖拽微调，单列一个阶段，有独立验收标准 |
| 后续 | Whisper 转写，仅在遇到无 transcript 素材时 |

第一阶段就能开始每天训练——这比"等一个完美的自动切句"重要得多。

## 素材管理的实施优先级

1. **本地文件导入**（音频 + 原文/LRC/SRT）—— 第一阶段必需
2. 切句结果人工微调 UI
3. RSS 自动抓取

RSS 虽最符合"零录入"理念，但优先级最低：手动下个 mp3 + 复制 transcript 只要两分钟，而核心循环不通系统就是零。
